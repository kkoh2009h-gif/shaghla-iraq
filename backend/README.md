# خادم شَغلة

خادم مستقل باستخدام FastAPI وSQLAlchemy. لا يستخدم Supabase أو Firebase.

## تشغيل محلي
1. ادخل إلى مجلد `backend`.
2. أنشئ بيئة Python وثبّت الحزم: `pip install -r requirements.txt`
3. شغّل الخادم: `uvicorn app.main:app --host 0.0.0.0 --port 8000`
4. فحص الخدمة: `GET /health`
5. توثيق وتجربة API: افتح `/docs`.

## واجهات API الحالية

- `GET /health` — فحص حالة الخدمة وإصدارها.
- `GET /jobs` — قائمة الوظائف النشطة.
  - `q`: بحث في العنوان والوصف والمنطقة والتصنيف.
  - `governorate`: المحافظة.
  - `work_type`: نوع العمل.
  - `category`: المهنة/التصنيف.
  - `min_wage` و`max_wage`: نطاق الأجر بالدينار العراقي.
  - `skip` و`limit`: ترقيم النتائج (الحد الأعلى 100).
- `GET /jobs/{id}` — تفاصيل وظيفة نشطة.
- `POST /jobs` — إنشاء وظيفة (MVP تجريبي).
- `POST /jobs/{id}/apply` — تقديم طلب (MVP تجريبي).

## حقول الوظيفة
العنوان، الوصف، التصنيف، المحافظة، المنطقة، الأجر بالدينار، نوع العمل، عدد الشواغر، ومعرّف صاحب العمل التجريبي.

## حالة الأمان — اقرأ قبل النشر
هذه نسخة تطوير وليست جاهزة للإطلاق العام. إنشاء الوظيفة والتقديم يقبلان `employer_id` و`worker_id` من التطبيق مباشرة؛ يمكن تزوير هذه القيم. لا توجد بعد مصادقة هاتف OTP حقيقية، أو JWT، أو أدوار مفروضة من الخادم، أو تحديد معدل الطلبات، أو لوحة إدارة محمية. لا تضع بيانات حقيقية ولا تنشر نقاط الكتابة للعامة قبل تنفيذ هذه الحماية.

## متطلبات الإطلاق
- ربط OTP بمزود SMS فعلي يدعم إرسال الرسائل إلى أرقام العراق +964 وإضافة مفاتيحه كأسرار بيئية.
- إنشاء جلسات آمنة والتحقق من هوية المستخدم على الخادم، لا من معرّف يرسله العميل.
- فرض أدوار العامل وصاحب العمل والمدير على كل نقطة API.
- PostgreSQL للإنتاج، نسخ احتياطي، وترحيلات قاعدة بيانات.
- حدود طلبات، سجلات تدقيق، سياسة خصوصية، وآلية بلاغات ومراجعة إعلانات.
- نشر API على استضافة مستقلة مع HTTPS؛ GitHub Actions يبني التطبيق ويختبره لكنه ليس خادماً دائماً للـ API.
